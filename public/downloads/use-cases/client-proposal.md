# Client proposal

Designed for: Consultants, agencies, and small firms preparing a proposal from discovery notes

Result: A structured proposal draft with the problem, approach, work plan, assumptions, and approval points.

## Operating guide

- **When to use it:** Use this workflow when you need a structured proposal draft with the problem, approach, work plan, assumptions, and approval points.
- **Lead Bot:** Researcher
- **Cadence:** When a person supplies the approved brief and starts the workflow
- **Typical first run:** 30–60 minutes for a first manual run

### Access for the first run

- The approved inputs listed on this page
- Only the files, sources, and services required for this run
- No sending, publishing, spending, or live-system changes without approval

## Bots

1. Researcher
2. Planner
3. Client Deliverables

## Information to gather

- Discovery notes
- Approved services and prices
- Client requirements and proposal format

## Workflow

### 1. Researcher

Organize the client's stated needs and relevant background

Output: A concise situation brief

Message to send:

Use the approved inputs I provide. Organize the client's stated needs and relevant background. Return this result: A concise situation brief. Ask me about missing information before you continue.

### 2. Planner

Build the proposed work plan and dependencies

Output: A scope and delivery sequence

Message to send:

Start with this result from Researcher: A concise situation brief. Build the proposed work plan and dependencies. Return this result: A scope and delivery sequence. Ask me about missing information before you continue.

### 3. Client Deliverables

Draft the proposal in the approved format

Output: A client-facing proposal draft

Message to send:

Start with this result from Planner: A scope and delivery sequence. Draft the proposal in the approved format. Return this result: A client-facing proposal draft. Ask me about missing information before you continue.

## Handoff rules

1. Researcher hands the approved output—a concise situation brief—to Planner.
2. Planner hands the approved output—a scope and delivery sequence—to Client Deliverables.

## Overall request

Draft a proposal from these approved discovery notes. Use the supplied scope, prices, and format. Mark every promise, price, date, and assumption for my approval.

## Decisions for a person

- Approve scope and exclusions
- Approve prices, dates, and promises
- Deliver the proposal

## First test

Draft a proposal from a fictional or closed project and verify every price and commitment against the source notes.

## Success checkpoint

The first run passes when a person can verify the final result against the supplied material and every decision listed below remains with that person. Draft a proposal from a fictional or closed project and verify every price and commitment against the source notes.

## If the workflow stalls

If a handoff is incomplete, return it to the Bot that produced it with the missing information marked. Do not move to the next Bot until a person approves the corrected result.

## Hermes Desktop setup

1. Open each Bot's page, download its .tar.gz profile, and import it from the Profiles screen in Hermes Desktop.
2. Review each imported profile's SOUL.md, Bot Passport, and requested access.
3. Run each step in that Bot's own chat and review the result.
4. Pass the approved result to the next Bot with the message provided for that step.
5. After the sequence works, you may create a group with the same Bots. In a group, @mention the Bot you want.
