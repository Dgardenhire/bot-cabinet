# New venture evaluation

Designed for: Founders and small teams deciding whether an idea deserves a real-world test

Result: An evidence-based venture brief and a small test with success, revise, and stop rules set in advance.

## Operating guide

- **When to use it:** Use this workflow when you need an evidence-based venture brief and a small test with success, revise, and stop rules set in advance.
- **Lead Bot:** Nova
- **Cadence:** When a person supplies the approved brief and starts the workflow
- **Typical first run:** 15–30 minutes for a first manual run

### Access for the first run

- The approved inputs listed on this page
- Only the files, sources, and services required for this run
- No sending, publishing, spending, or live-system changes without approval

## Recommended starting Bot

1. Nova

One Nova can evaluate an early idea and propose a small test. Add Researcher for a deeper evidence review, or Pulse when a live experiment needs dedicated measurement.

Optional specialists: researcher, pulse.

## Information to gather

- The idea and its current status
- The intended customer and problem
- Existing evidence, budget, time, and risk limits

## Workflow

### 1. Nova

Separate facts from assumptions, check the most important unknowns in the approved sources, and design one low-cost test

Output: A venture brief, evidence notes, and a test with success, revise, and stop rules

Message to send:

Use the approved inputs I provide. Separate facts from assumptions, check the most important unknowns in the approved sources, and design one low-cost test. Return this result: A venture brief, evidence notes, and a test with success, revise, and stop rules. Ask me about missing information before you continue.

## Overall request

Evaluate this idea without treating it as a commitment. Separate evidence from assumptions, check the most important unknowns, and propose one low-cost test with decision rules for my approval.

## Decisions for a person

- Confirm the idea's status and risk limits
- Approve any spending, outreach, or public claim
- Decide whether to continue, revise, or stop after reviewing the results

## First test

Use one idea and approved public sources to design a no-spend test. Approve the decision rules before running it.

## Success checkpoint

The first run passes when a person can verify the final result against the supplied material and every decision listed below remains with that person. Use one idea and approved public sources to design a no-spend test. Approve the decision rules before running it.

## If the workflow stalls

If the result is incomplete, mark the missing information and ask the same Bot to correct it. Add another Bot only when a genuinely separate role or independent check would help.

## Hermes Desktop setup

1. Open the linked Bot's page, download its .tar.gz profile, and import it from the Profiles screen in Hermes Desktop.
2. Review the profile's SOUL.md, Bot Passport, and requested access.
3. Run the complete request in that Bot's chat with low-risk material and review the result.
4. Add a schedule, outside connection, or optional specialist only after the manual version works.
