# Turn product feedback into a decision list

Designed for: Small teams deciding what to investigate before adding features

Result: Grouped requests with customer references, reported problems and unanswered questions kept distinct.

## Try a sample first

Illustrative example, not a recorded Bot run. This adaptation has not been runtime-tested.

### Complete first request

Group feedback by the problem people are trying to solve. Keep source and customer IDs, distinguish duplicate reports from independent demand, and separate reported bugs from requested features. Propose the smallest useful investigation without inventing priority, revenue, customer commitments or a delivery date Use only the records I supply. Label missing or uncertain information. Do not connect accounts, browse, send, submit, publish, spend money or create a schedule. Return a draft for my review.

Fictional feedback. F1, customer C1: 'CSV export is blank on my phone.' F2, customer C1: the same report forwarded by sales. F3, customer C2: 'Please add XLSX so our accountant can open the file.' F4, customer C3: 'We cannot find the existing CSV button.' No reproduction, browser details, revenue or promised dates are supplied.

### Example result

Export failure: F1 and F2 are one customer's report, not two independent requests; reproduce on the reported device after obtaining browser details. Spreadsheet format: F3 requests XLSX; ask whether existing CSV meets the accountant's need before building. Findability: F4 concerns an existing button; check the navigation and instructions. Three distinct customers supplied four records. No bug is reproduced, feature approved or delivery date promised.

### Check the answer

- Count three customers, not four independent votes.
- Keep the reported failure separate from XLSX and findability.
- Suggest investigations without claiming a verified bug or approved roadmap.

## Operating guide

- **When to use it:** Use this workflow when you need grouped requests with customer references, reported problems and unanswered questions kept distinct.
- **Lead Bot:** Nova
- **Cadence:** When a person supplies the approved brief and starts the workflow
- **Typical first run:** 15–30 minutes for a first manual run

### Access for the first run

- The approved inputs listed on this page
- Only the files, sources, and services required for this run
- No sending, publishing, spending, or live-system changes without approval
