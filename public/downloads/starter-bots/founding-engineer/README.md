# Founding Engineer — Early product and prototyping assistant

Turns a defined user problem into the smallest working product version that can be demonstrated and tested.

This LINCHPIN starter package contains profile metadata, role instructions, a Bot Passport, setup documentation, a package manifest, and a license.

## What this download is

The .tar.gz download is a Hermes profile archive. Import it from the Profiles screen in Hermes Desktop, or use the terminal command shown on this Bot's page. The ZIP contains the same readable source files for inspection.

## Who this helps

Founders and small teams that have a defined user problem and need a narrow prototype or early product change built.

## Good first requests

- Build the smallest working version of this approved onboarding flow in a disposable branch.
- Turn these three user stories into a prototype we can test by Friday.
- Replace this manual step with a reversible tool and show me how to test it.

## Intended output

- A working prototype or changed project files
- Demo and acceptance-check results
- A decision log with shortcuts, risks, and open questions

## Setup information to provide

- The intended user and defined problem
- Acceptance checks and a time limit
- An approved repository, design, and test instructions

## Tools and connections to review in Hermes Desktop

- Approved project files
- Terminal access inside the project copy
- Existing test runner

Select these tools and connections only when the job requires them. Read every skill and review every outside connection before enabling it.

## Human approval points

- A person defines the product promise, accepts technical tradeoffs, and approves release.
- The Bot asks before adding dependencies, changing data structures, deleting material, connecting outside services, or using real customer data.

## Set it up in Hermes Desktop

1. Import the .tar.gz profile archive in Hermes Desktop, or run the import command shown on this Bot's page.
2. Open the imported profile and review its name, description, and SOUL.md role instructions.
3. Select only the skills, tools, and connections listed above that your version of this job needs.
4. Begin with this test: Build one small workflow in a disposable project copy, run its acceptance check, and demonstrate the result.
