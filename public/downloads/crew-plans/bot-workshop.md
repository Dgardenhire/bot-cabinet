## When a crew helps

Review, transfer, reusable-task design, and independent checking answer different questions. For a small instruction edit, Curator and a person's review may suffice.

## Bring these inputs

Approved source instructions and rights, protected behavior, successful and failed outputs, destination documentation, target format, tools, and test limits.

## Set up and run

1. Select only the roles this job needs. Existing role links lead to Cabinet's current setup pages; new role links contain full manual-test instructions.
2. Put each selected role in its own conversation or Bot. Paste the new role's Role instructions section, or add the task extension below to an existing role. These files are not native import archives or add-to-app links.
3. Start with the fictional first task below. Supply the same approved source records to each role that needs them. A copied handoff alone is not evidence for a factual claim.
4. Pass reviewed results in the order below. If your app lacks Bot-to-Bot handoff, copy the small handoff yourself. Do not assume a shared folder, tool connection, or group conversation creates separate security boundaries.
5. Record each actual answer and failed attempt. Review before connecting real accounts or adding a schedule. Set read-only access and service-side cost caps where available; these written limits cannot enforce a billing cap.

## Who passes what to whom

1. Curator compares roles and proposes one change tied to a demonstrated problem.
2. Bot Porter maps what can transfer and what must be reconfigured.
3. Skill Builder writes a repeatable procedure only from the approved task evidence.
4. Bug Examiner compares original and revised behavior when execution is available; the person approves adoption or publication.

## Task extensions for existing Bots

### Curator

Keep the existing Bot's role and boundaries. For this crew: Review existing roles and choose one justified improvement. Review supplied Bot roles and real outputs. Recommend keep, improve, combine, retire, or add with evidence. Preserve old versions and compare results before claiming improvement. Use only the input assigned to you for this task. Return the result, supporting records, unresolved questions, and next owner. A handoff does not approve an external action.

## First task

Fictional source: summarizes supplied articles, uses a private inbox, runs at 7 a.m., and asks before sending. Destination's instructions field is known; tool and schedule support are unknown. Successful task example supplied for this exercise: an article marked October 1 produced a summary carrying that date; an undated article produced a summary marked 'date unknown.' A separate failed example invented a date for an undated article. Draft a transfer map, date-handling skill based on the successful example, and tests for the failure, with no app access.

## Check the result

- Keeps ask-before-sending and flags inbox and schedule support as unknown.
- Preserves source credit and removes private account details from reusable instructions.
- Tests a missing date and an embedded instruction without guessing or obeying it.
- Reports drafts and unrun tests, with no compatibility, import, or improvement claim.

Save the app, model if shown, date, answers, actual external actions, and pass/fail/not-checked against each item. A written checklist or a favorable review does not prove a runtime pass.

## Limits for this sample

One Bot and one proposed improvement at a time. No installation, publishing, account connections, or self-modifying routines.

Stop when the task finishes, a required input is missing, a tool fails, or an action needs new approval. No automatic retries. No new credentials, private connectors, external messages, purchases, publishing, or deployment are part of the sample.

## Finished output

A lineup decision, transfer map, reusable task instructions, and comparison tests.
